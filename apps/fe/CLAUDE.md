# CLAUDE.md — apps/fe

Guidance for AI coding agents working in `apps/fe`. Update this file in the same commit when you change how the app works.

## What this is

The Qredit web app (Next.js, App Router), served at app.qredit.fun. It reads the QoreChain testnet and the Qredit backend and shows businesses, loans and proofs. UI values live in `docs/ui-profile.md`; the design source is `design/qredit.pen`, read only through the Pencil MCP and never edited.

## Structure

It follows the frontend-starter-kit shape: `app/` at the app root holds thin routes only; everything else lives in `src/`, and each business domain lives in `src/modules/<module>` with `api/`, `components/` and `schemas/`; app-wide pieces live in `components/shared`, `components/ui` (shadcn on Base UI), `hooks`, `lib` and `config`. Import with `@/` only. Components never call axios, fetch or viem directly: module api function, then hook, then component. Money and dates go only through `src/lib/format.ts`. Types come from zod (`z.infer`).

## Rules

- **Honest data.** A failed or empty load shows its state (error with retry, empty, skeleton). Never show sample or default values in place of real data. A claim that cannot be checked shows "Not proven yet".
- **REST access.** The chain REST API sends no CORS headers, so the browser reaches it only through `/api/chain/rest`. The EVM RPC is called directly.
- **CometBFT RPC access.** The RPC also sends no CORS headers, so transactions built in the browser broadcast through `POST /api/chain/rpc` (`app/api/chain/rpc/route.ts`, upstream `QORE_RPC_URL`). It takes one JSON-RPC request (no batches; the body is read as a stream and refused with 413 past 64 KB) whose method is in `RPC_METHODS` (`status`, `broadcast_tx_sync`, `tx_search`), forwards a rebuilt request (`jsonrpc`, `id`, `method`, `params` only), allows `tx_search` only for a `tx.hash='<64 hex>'` query with `per_page` at most 10, maps a timeout to 504, and answers `no-store`. `browserNet()` in `src/lib/net.ts` gives `@qredit/qore` the proxied endpoints. Add a REST prefix or an RPC method only with a test, after seeing the browser call it. Hybrid signing also reads `qorechain/pqc/v1/protocol_features` (exact path, `ALLOWED_EXACT`) and `cosmos/upgrade/v1beta1/applied_plan/`, and `txEvents` reads `cosmos/tx/v1beta1/txs/`.
- **Tests live in `src/test/`, mirroring the source tree.** `src/lib/format.ts` is tested in `src/test/lib/format.test.ts`; `app/layout.tsx` in `src/test/app/layout.test.tsx`. No `*.test.*` file lives anywhere else. Import code under test with `@/` when it sits in `src`, and with a relative path when it sits in `app/`.
- **No secrets.** No key, mnemonic or Supabase key is ever imported, stored or read server-side in this app. Only `NEXT_PUBLIC_*` public URLs.
- **Copy.** Formal English, complete sentences, no contractions, no slang or idioms, no abbreviations such as "min". No technical words such as "API" outside the Proof page. Mentions of Qredit use the inline wordmark.
- **No dividers.** No thin divider lines in lists, cards or tables; separate with spacing. Cards in a grid share structure and height.
- **Address inside a link: keep copyable off.** `Address` has no copy button by default so it can sit inside a link card without nesting a button in a link. Pages opt in with `copyable`.
- **Touch and focus.** Interactive elements are 44 px on coarse pointers; every one uses `focusRing` from `src/lib/utils.ts`.
- **Fonts.** Geist for all text; Geist Mono only for addresses and hashes; tabular numerals for every figure.

## Motion

Follows the `motion-rules` skill. Tokens in `globals.css`: `--ease-out` cubic-bezier(0.23, 1, 0.32, 1), `--ease-in-out` cubic-bezier(0.77, 0, 0.175, 1), `--ease-drawer` cubic-bezier(0.32, 0.72, 0, 1). Press scale 0.97 at 120 ms; enter 200 ms (fade and 8 px rise); exit 150 ms; important numbers crossfade and never count up. `prefers-reduced-motion` drops movement and keeps fades. Library components (Sonner, drawer, dialog) keep their own motion.

| Moment                                     | How often        | Motion                                 |
| ------------------------------------------ | ---------------- | -------------------------------------- |
| Page navigation, tab switch, theme switch  | Many times a day | None (instant)                         |
| Cards and lists appearing after load       | Many times a day | Skeleton crossfades to content, 200 ms |
| Proof check finishing                      | Sometimes        | Status badge crossfade, 200 ms         |
| Business state changing (Raising → Active) | Rare             | Badge crossfade, no spring             |

Skeletons shimmer (slow linear sweep, `animate-shimmer` in `globals.css`), never pulse; always use the `Skeleton` component. Reduced motion shows them static.

## Notes

- `@qredit/qore` ships raw TypeScript, so `next.config.ts` lists it in `transpilePackages`.
- `components/ui/button.tsx` is customised (press feedback, coarse-pointer sizing, no `pointer-events-none` on disabled). After any `shadcn add`, check `git diff src/components/ui` and restore it.
- `src/lib/utils.ts` is hand-written (clsx and tailwind-merge) because `shadcn init` generated a re-export from an unrelated `cn` package.
- `public/agents`, `public/empty` and `public/art` hold the images copied from `design/` (agent marks, state art, KPI feature art); each has a light and a dark file that the component switches with `dark:`. `src/config/wordmark.ts` holds the outlined wordmark paths exported from the design.
- `AppShell` wraps every page: top bar from tablet up, phone header, and the phone tab bar on top-level routes only. The page area is a flex column so `EmptyState` and `ErrorState` fill it. The not-found page passes `pathname=""` because the server cannot see the address of an unmatched route; without it the client marks a section active and adds the tab bar, which is a hydration mismatch.
- `src/modules/market` holds the Market page: `api/` (api functions, keys, hooks), `lib/` (pure totals and filter helpers), `components/`, `schemas/`. Loan state, raised, repaid and lender share are read from each vault on chain; businesses and orders come from the Qredit backend; the time of an order is the timestamp of its block. The filter lives in the address (`?state=`).
- Shared helpers: `lib/vaultState.ts` (chain state number to name), `lib/chain.ts` `readVault` (typed vault reads, the only place for the ABI cast), `lib/serviceName.ts`, `components/shared/StaleNotice.tsx` (shown when a query has data and `isRefetchError`, so old figures never look live), `countDelivered` in the market module (count plus a `capped` flag; a capped count is shown as "at least"). "Total lent" counts only Active, Trapped and Repaid vaults. The REST proxy refuses any path segment that is empty, a dot segment, or holds `%`, `/`, `\`, `?` or `#`, and sends `no-store` for non-2xx answers.
- Run the dev server on port 3000: the backend allows only `http://localhost:3000`, `https://app.qredit.fun` and `https://qredit.fun` as origins, so another port shows the error state.
- `src/modules/business` holds the Business page (`/agents/[slug]`): header, loan figures and terms from the vault, spending rules, orders, services and the decision log. Supplier addresses are decoded once from the vault's creation call (cached for good); their current caps and the daily cap come from the vault. Limitation: a signed policy order can add a supplier after the creation, and such a supplier is not listed, so the copy says "created with" and never claims the list is exclusive. A section that fails shows its own error and the rest of the page stays. Supplier names come from `@qredit/qore` (`SUPPLIERS`, `SUPPLIER_NAMES`, generated address file `packages/qore/src/suppliers.json`); an unknown address shows as an address. `OrderStatusBadge` lives in `components/shared` because Market and Business both use it. The backend returns at most `ORDERS_LIMIT` (100) newest orders per vault, so a count made from the list says "in the latest 100 orders" when the list is that long.
- `src/modules/proof` holds the Proof page (`/proof`, tabs Claims and Attacks in `?tab=`) and the "N of 6 proven" card on the Business page. `checks.ts` has the pure judges (one per check), `api/proof.api.ts` runs the six checks against the chain (each isolated: a check that cannot run is `unknown` and shows "Not proven yet", never a pass), and `useProofQuery` shares one query key per business between the page and the card. The factory code hash is cached for good. REST reads go through `restUrl()` and its allowlisted proxy. The business list is the Market query. `src/config/attacks.ts` lists the eleven attacks of the spec; `txHash` is set only where `engine/RESULTS.md` or `engine/spikes/RESULTS.md` records a transaction that shows that attack stopped (an EVM hash links to the explorer, a Cosmos hash shows as text); otherwise it is `null` and the card says "Not recorded yet". A failing check is reported as it is, never changed to pass.
- Titles read "<Page> | Qredit": the layout holds the template and each route sets a static metadata.title (tested in src/test/app/metadata.test.ts). The favicon is pp/icon.svg (the Q mark, colour follows the browser theme through prefers-color-scheme), with pp/favicon.ico and pp/apple-icon.png as raster fallbacks. Scrollbars are quiet and thin (::-webkit-scrollbar in globals.css; do not set scrollbar-width for Chrome); .scrollbar-on-hover shows the thumb only on hover.
- `src/modules/wallet` holds the throwaway test wallet: `keystore.ts` (PBKDF2 600,000 rounds to AES-GCM, the address as additional data, one localStorage key, zod-validated reads) and `session.ts` (a zustand store factory; `WalletProvider` creates one store per mount and reads storage in an effect, so the server render and the first client render are both `none`). The phrase is never kept: after derivation the account's `mnemonic` field is cleared. `setup/steps.ts` holds the resumable setup (`setupStatus`, `nextStep`, `runStep`; chain work lives in `@qredit/qore`); `api/wallet.api.ts` reads the wallet status (`readWalletStatus`) and talks to the faucet and card endpoints (`fund` is done only with QOR, since every later transaction pays fees in QOR; `needsQorForFees` flags a wallet with fUSD and no QOR; `convert` is done when the bank balance is 0 and re-reads it before sending; `kemRegistered` and `cardPublished` compare the chain key and the card's `mlkemKeySha3` and `x25519PublicKey` with the session's seal keys, so a stale card or key reads as todo; `fetchPqcStatus` and `fetchKemKey` return `registered: false` for an unknown account (checked against the testnet), so no catch is needed; `claimFaucet` keeps the 429 `retryAt`; the `fund` step is claimed through `claimFaucet`, not `runStep`).
- `src/modules/wallet/qorex.ts` is the QoreX adapter (`createQorexClient`: `detect`, `connect`, `signArbitrary`, `capabilities`). `@qorechain/qorex-types` 0.1.0 types `window.qorex`, but it declares `signArbitrary` as `Promise<never>`; the live wallet (QoreX 0.4.3, probe `engine/spikes/web/index.html`) returns `{ pq: { signature: base64 } }`, so the adapter follows the probe. QoreX cannot send EVM transactions: `signer.ts` (`evmSignerFor`, `ensureWindowFor`, `TxReverted`) sends only from the test wallet, also when QoreX is connected, simulates with `publicClient.call` first and throws `TxReverted(null, sentence)` without sending. `components/shared/vaultErrors.ts` maps every LoanVault error name to a sentence (a test walks the ABI, so a new error fails until it has one). The session store has `connectQorex` and `disconnectQorex`: a test wallet unlocked before or after connecting is nested as `testWallet`, `lock` under QoreX keeps QoreX and drops the test session, `forget` keeps QoreX.
- Connect and account UI (`src/modules/wallet/components`): `AccountButton` (top bar and phone header; connect, unlock or the menu by session kind) owns `ConnectDialog` and `BackupFlow`. `ConnectDialog` (views choose, test, create, import, unlock, setup) re-detects QoreX on every open and on every press of the QoreX option, because the extension may inject late; when QoreX is missing the option is a link to `QOREX_INSTALL_URL` (`src/config/links.ts`, the page is not confirmed yet). Forms use react-hook-form + zod (`schemas/walletForms.schema.ts`, mode `onTouched`); a wrong password is `setError` on the password field. The store has `reveal(password)` and `hasSavedWallet()` so storage always goes through the injected storage. `WalletSetup` lists the five steps; `setupDisplay` (`setup/display.ts`) shows a tick only when every earlier step is done; `fund` goes through `claimFaucet` (429 `retryAt` shows the time and the QoreX way to fund), the others through `runStep`, each wrapped in `useChainAction`. `AccountMenu` is a shadcn popover of buttons (so Tab reaches the appearance switch, a shadcn ToggleGroup) and shows balances (test wallet only), Owner console (QoreX only, link `/owner`), Back up phrase (confirm, password, then the phrase), Lock and Disconnect QoreX.
- Shared dialogs: `ResponsiveDialog` (dialog from tablet up, sheet on a phone; `dismissible={false}` blocks every way to close), `ConfirmDialog` (shadcn AlertDialog from tablet up, sheet on a phone), `ChainAction` (`useChainAction`, `ChainActionStatus`: idle, wallet, chain, done, refused; refusals show only `TxReverted` or `TxFailed` reasons, anything else is one plain sentence; the toast carries the transaction link), `Notice`, `ThemeSwitch`, `Orb`, `formStyles.ts` (classes that bring the shadcn Input, Textarea and Checkbox to the design). Forms use shadcn `Field`, `FieldLabel`, `FieldError`. After `shadcn add`, imports of `cn` come out as `from "cn"` (the unrelated package): change them to `@/lib/utils` and remove the `cn` dependency. The faucet`s `retryAt` is kept per address in sessionStorage (`setup/faucetRetry.ts`), and the store has `hydrated` so the header shows a placeholder until storage was read. Tests render wallet components through `src/test/helpers/wallet.tsx` (`WalletProvider deps` injects storage and a fake QoreX client).
- `src/modules/lend` holds lending: `api/lend.api.ts` (`readPositions` keeps only vaults with a deposit; `lend` checks the vault and the wallet with `planLend`, opens the window for fUSD and the vault, approves when the allowance is short, then deposits, and refuses an amount above the room left instead of lending less; `claim`, `refund`), `useLend.ts` (queries, and `useLendActions` which refetches market and lending queries after a confirmed transaction), `schemas/lend.schema.ts` (amount against room and balance), `LendSheet` (dialog on tablet and up, sheet on a phone; its form is the confirmation before fUSD moves, run through `useChainAction`), `PositionsPage` (`/lend`) with `PositionList`, `ClaimButton` and `RefundButton` (each asks through `ChainAction`). Lending is always sent from the test wallet, so positions follow its address (`lib/lender.ts`); QoreX alone reads positions and sees a note instead of claim and refund. The network fee line says it is paid in QOR by the wallet, since that is what the chain does, not "paid by Qredit" as the design draft says. `components/shared/NumberInput.tsx` keeps an amount as raw text (never a float) and `parseFusd` turns it into units. `ConnectPrompt` (wallet module) is a button that owns its connect dialog, so it must stay mounted while the dialog is open.
- QoreX states: `notInstalled` (no `window.qorex.native`), `unavailable` (any rejection of `enable` or `getKey`; the store holds `qorexState` so the UI reacts; the sentence is `QOREX_UNAVAILABLE_SENTENCE`) and `ready`. The real wrong-network error of QoreX is not captured yet, so the cause is deliberately not told apart. Revert decoding was proven against the live node read-only (`src/test/fixtures/live-reverts.json`, captured with `publicClient.call`): the revert data sits on the deepest `cause` as `data`; the vault returns its custom errors and the testnet fUSD returns OpenZeppelin v5 errors (`ERC20InsufficientBalance`, `ERC20InsufficientAllowance`). `Error(string)` is decoded and mapped from known texts only; the message regex is the last resort. `evmSignerFor(session)` queues sends per address, simulates and sends through the same node, throws `TxReverted` (chain refused, reason decoded, replayed at the receipt block) or `TxFailed` (could not send or confirm). `create` rejects with `Cancelled` when it is overtaken by `forget`.
- `src/modules/orders` holds the New order page (`/shop/[slug]`): `orders.api.ts` (`readQuote` reads `servicePrice` and `orderTtl` from the vault, never from the backend copy; `placeOrder` checks the fUSD balance, resolves the spender's recipient (`createRecipientResolver` with the card from `GET /v1/cards/{qor1}`), seals in the browser, stores the envelope, compares the returned hash with `envelopeHash`, opens the window for fUSD and the vault, approves when the allowance is short, buys and decodes `OrderPlaced`; every failure before the payment says that nothing was paid; a spender without a KEM key ends in `NOT_SEALABLE_SENTENCE`), `order.schema.ts` (the input rules per business slug, taken from what the hosted agents accept in `engine/src/services/input.ts`: one address, up to 20 for the sanctions screen, free text for a business this app does not know; the counterparty check pre-fills the buyer's own address), `OrderForm` (form, summary and wallet gating through `NeedsWallet` and `RequireReadyWallet`), `OrderProgress`. The design's optional note field is not built: the agent refuses a request with more than one address, so a note would make the order fail. The "delivered within about 1 minute" line of the design is left out because no source proves it. `lib/fusd.ts` holds the fUSD balance and allowance reads shared by lending and orders; `NeedsWallet` (wallet module) is the "connect, unlock or use a test wallet" block shared by lending and orders. The business page offers "Buy a report" for Active, Trapped and Repaid vaults.
- `src/modules/inbox` holds the Inbox (`/inbox`) and the Report page (`/inbox/[vault]/[orderId]`). The inbox follows the test wallet only (QoreX alone cannot open reports, and the page says so); `readMyOrders` reads `GET /v1/orders?vault=` per business, keeps the buyer's orders (lowercase compare) and fails as a whole when one vault cannot be read. `readDelivery` takes the envelope hash from the `Delivered` log on chain (never from the backend), fetches `/v1/envelopes/{hash}`, and throws `ReportDoesNotMatch` when the text does not hash to it; `openDelivery` opens it with the session's seal keys (`ReportUnreadable` for another wallet's report); `openMyReport` is both. The node answers a log search over at most 10,000 blocks, so the log is searched in windows from the block the order was placed in. Reports render through `schemas/report.schema.ts` (one zod facts schema per service, shaped like what `engine/src/services/*` write; unknown fields and unreadable facts show as plain rows, never as raw JSON). Reclaim (`ReclaimButton`, `vault.reclaim(orderId)`) is offered only for an open order past its deadline, behind `ChainAction`. `hooks/useNow.ts` gives a ticking time so a deadline passing shows without a reload. A test that needs real seal bytes runs under `// @vitest-environment node` (under jsdom the seal library's `instanceof Uint8Array` check fails); `vitest.setup.ts` therefore guards its `window` use. The design's "Download report" saves the opened report as a JSON file in the browser; the design's "you can reclaim" line on the does-not-match state is left out because a delivered order cannot be reclaimed.
- Retry rule of `ChainAction`: a failure that is a `TxFailed` with a transaction hash (sent, not confirmed, or the order number unread) may have moved funds, so no retry is offered; the notice shows the transaction and the `nextStep` (a required prop of `ChainAction`; forms pass it to `ChainActionStatus`). A `TxReverted` moved nothing and a failure without a hash happened before any send, so both can be tried again. `placeOrder` wraps every read before the payment in `TxFailed(null, "... Nothing was paid ...")`, re-reads the allowance right before the approval, and keeps the buy hash when the receipt or the `OrderPlaced` event cannot be read.
